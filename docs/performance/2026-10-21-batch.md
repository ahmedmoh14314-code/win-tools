# Batch processing: measurements (2026-10-21)

Machine: the development PC (12 logical processors, Windows 11 Pro 26200), Release builds, .NET 10.0.13.

## Worker pool size
100 photos of 1200×900 converted to WebP through `WorkerClient`, wall time for the whole batch, worker start included:

| Lanes | Time | Speed-up |
|---|---|---|
| 1 | 20.9 s | 1.0× |
| 2 | 9.9 s | 2.1× |
| 4 | 6.1 s | 3.4× |
| 6 | 4.7 s | 4.4× |
| 8 | 4.1 s | 5.1× |

The default is half the logical processors, capped at 4 (ADR-0005). Beyond 4 the gain flattens while the worst-case memory grows with every lane.

## Explorer end to end
`tests/WinTools.EndToEnd batch`: Ctrl+A in a real Explorer window, drag, Space, drop on a Convert command.

| Files | Runs | Result |
|---|---|---|
| 12 | 3 | 3/3 passed: every output valid, sources unchanged by hash, no stray files, one accepted drop each |
| 60 | 1 | 1/1 passed: `job.done` ok=60 in 353.6 ms (small PNG → JPEG) |

Not measured: batches of large images, memory peak of a full 4-lane batch at the size limits (TASK 5).
